# ADR-0003: 生成能力の追加と「サーバー制約の緩和」

- ステータス: 採択
- 日付: 2026-07-22
- 関連: ADR-0001（基盤）, ADR-0002（製品方向・大型 substrate）

## 背景

ユーザーから2つの方針が示された:
1. 「普通に GPT 的に使えるようにしたい」＝**文章生成（会話）能力**が欲しい。
2. 「みんな使っても無料でいけるならサーバーやネット通信もあり。ただし仕組みは
   自作でオリジナルなら」＝**サーバー制約の条件付き緩和**。

## 決定1: 生成能力を追加する（小型因果 LM を自前実装）

これまでの substrate（deberta / e5）は**エンコーダ**で文章を生成しない。GPT 的な
体験には**因果デコーダ（生成）LM が別途必要**。方針:

- **小型の生成 LM を自前実装**（例: rinna/japanese-gpt2-small ~110M・SentencePiece・
  MeCab 非依存）。e5 と同様に重みを抽出・量子化し、因果デコーダ forward + KV
  キャッシュ + サンプリングをゼロから実装する。
- **既存 LLM API のラッパーにはしない**（原則維持）。生成の主権は自作モデル/エンジン。
- 正直な限界: 端末で回せる小型モデルの生成品質は **GPT-3.5 級には届かない**
  （短い・ぎこちない日本語）。過大な期待は置かない。

## 決定2: サーバーは「無料でスケールする範囲」で許可（推論はクライアント）

「多人数でも無料」という条件は、実質 **推論をクライアント側で行う**ことを要求する
（サーバー推論はユーザー増で課金が増え、無料でスケールしない）。したがって:

- **生成（重い計算）は各ユーザーの端末で行う**（クライアントサイド推論）。これが
  「無料スケール」と「オリジナル」を両立する唯一の現実解。決定1 と一致する。
- **サーバー/ネット通信は"無料でできる軽いこと"に限定して許可**:
  - 大きめモデル重みの配信（無料 CDN: Cloudflare R2/Pages 等。GitHub Pages/LFS の
    帯域・ヘッダ制約から解放される）。
  - 将来: 無料枠の軽量バックエンド（Cloudflare Workers / Supabase 等）で同期・
    Pack 共有・匿名テレメトリなどを**自作**する（既存 AI API は使わない）。
- **既存 AI 推論 API（OpenAI/Anthropic 等）は使わない**（原則②「自作・オリジナル」）。

### 得られること / 変わらないこと

- 得: 配信先が GitHub Pages に縛られず、選べるモデルサイズが上がる。
- 変わらず: 推論はローカル（端末）。生成エンジンは自作。忘却・記憶・概念・メタ認知
  の自己成長アーキテクチャ（ADR-0001/0002）はそのまま。

## ロードマップへの含意

- **Phase 5（生成能力）を最優先の次段**とする。詳細は `docs/phase-5-plan.md`。
  - 5a: iOS WebGPU 生成の実現性スパイク（載るサイズ・tokens/sec）。← 最初に潰す。
  - 5b: 小型因果 LM の抽出 + forward + KV キャッシュ + サンプリング（WebGPU）。
  - 5c: 記憶接地生成（RAG）+ チャット UI ＝「GPT 的だがユーザーごとに育つ」。
- ADR-0002 の「大型 substrate（任意の上位層）」は、無料 CDN 配信でより現実的になる。
- **生成には WebGPU forward が必須**（自前 JS では per-token が遅すぎる）。Phase 0
  以来先送りしてきた Runtime の GPU 経路への投資が、ここで必要になる。

## 更新（2026-07-22）: GitHub Pages のまま・小型モデル・知識は GitHub データに

ユーザーの追加方針で、配信は **GitHub Pages に戻す**（外部 CDN は使わない）。
そのため:

- **モデルは小型に保つ**（GitHub Pages: 単一ファイル 100MB / リポジトリ ~1GB に収める。
  必要ならチャンク分割・量子化強化・より小さいモデル）。小型なので帯域も問題に
  なりにくく、OPFS キャッシュで再訪はローカル。
- **知識は「モデルの大きさ」でなく「GitHub 上のデータ」で持つ**。学習データ/知識を
  GitHub に置き（バージョン管理・更新可能）、実行時に **RAG（検索して接地）** で使う。
  → 小型モデルのまま、データを増やせば知識が増える。
- RAG の検索基盤は既存の Memory Fabric・埋め込み・想起をそのまま流用できる。
- 正直な限界: RAG は関連性・事実性を上げるが、**生成の流暢さは小型モデルの限界の
  まま**（GPT-3.5 級には届かない）。「知識はデータで、"らしさ"は記憶接地で」。
