# Phase 1 結果記録

- 実施日: 2026-07-21
- 対象: Representation（自作エンコーダ）+ Memory Fabric（最小）
- 前提: `docs/phase-1-spec.md`
- 状態: **数値コアは Node で検証済み（下記）。iOS 実機確認は次段で実施。**

## 数値検証（Node, CPU バックエンド）

コーパス8文（雨クラスタ4／動物クラスタ4）、D=64, window=2, lr=0.1, 40エポック。

| 受け入れ条件 | 結果 | 実測 |
|---|---|---|
| #1 符号化の安定性（同一入力→同一出力） | ✅ | encode 決定的 |
| #2 オンライン学習（loss 低下） | ✅ | CBOW loss 3.31 → 1.47 |
| #3 意味的想起（関連文が上位） | ✅ | 「雨の日は傘が必要だ」→ 上位に雨クラスタ（1位「今日は雨が降っている」） |
| #4 観測できる忘却 | ✅ | decay 後 retention: 高可塑(雨)0.259 < 低可塑(動物)0.861 |
| #5 永続化 bit 一致 | ✅ | encoder / memory とも serialize→deserialize→serialize がバイト一致 |

補助: reinforce で retention が上がり（0.259→0.509）、想起順位を回復できることも確認。

## 実装で判明した重要な知見

### 1. char 平均プーリングは高頻度文字に支配される → IDF 重み付けで解決

素の char 平均は助詞（は・が・を・の）に埋もれ、内容語（雨・傘・犬・猫）が効かず
想起が無関係文に流れた。文書頻度 df から求めた **IDF 重み付け**（全件に出る文字を
0 に近づけ、内容語を強調。SIF 系の考え方を char 単位に適用）で内容語が効くように
なり、想起が改善した。ライブラリ非依存で実装。

### 2.【要注意】tiny corpus では char-CBOW が過学習し表現が崩壊する

同一の小コーパスで学習を回しすぎる（200〜300エポック）と、全文の表現が最長文
（"犬と猫はどちらも動物だ"）に吸い寄せられ、想起が壊れた。エポック数を振ると:

| エポック | loss | 「雨」クエリの想起 |
|---|---|---|
| 30〜50 | 3.31→約1.4〜1.6 | ✅ 雨クラスタが上位 |
| 80 | 3.31→1.28 | △（D により崩れ始める） |
| 200〜300 | さらに低下 | ❌ 全部が最長文に collapse |

- 対策として **1回の学習を控えめ（40エポック）** にした。埋め込み次元は D=64 が
  D=48 より頑健（80エポックでも崩れにくい）。
- **本質的な含意**: 単一デバイス・少データでは、表現をゼロから学習すると過学習と
  崩壊が避けにくい。これは ADR-0001 の substrate 方針（凍結した事前学習言語器官を
  土台にする）の妥当性を実証データで裏付ける。Phase 2 で substrate を Representation
  に差し込めば、この崩壊問題は大きく緩和されるはず。

### 3. Runtime 抽象は想起の類似度計算で実際に使われている

recall の「クエリ(1×D) × 全記憶(D×N)」は backend.matmul 経由。Phase 0 で作った
Runtime 抽象が Phase 1 の実処理で行使され、CPU/GPU 差し替え可能なまま動く。
