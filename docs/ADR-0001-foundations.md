# ADR-0001: Browser AI Runtime の基盤決定

- ステータス: 採択（Phase 0 開始）
- 日付: 2026-07-21
- 対象: プロジェクト全体の土台となる方向性

このドキュメントは「なぜそう決めたか」を残すための決定記録（Architecture
Decision Record）である。ここに書かれた決定は、より良い根拠が出れば改訂して
よい。改訂する場合は新しい ADR を追加し、本 ADR のステータスを更新する。

---

## 0. プロジェクトの定義（何を作り、何を作らないか）

作るもの:

- **Browser AI Runtime** — HTML / CSS / JavaScript(TypeScript) のみで動く、
  完全クライアントサイドの AI 実行基盤。
- 対象は **iPhone / Safari / PWA を最優先**。
- サーバー禁止・AI API 禁止・クラウド推論禁止。**完全ローカル実行**。
- その上で動く最初のアプリとして **AI Reporter** を予定。ただし AI Reporter
  は最終目標ではなく、最終目標は Runtime そのものの完成。

作らないもの（明示的な非目標）:

- ChatGPT のコピー / 既存 LLM のラッパー。
- Transformer の単なる再実装。

---

## 1. 決定した3本の柱

### 柱1: 言語能力の「起点」= 小型事前学習モデルを土台に継続学習

**決定**: ゼロから言語を育てるのではなく、小型の事前学習済みモデルを土台と
して読み込み、その上で自己成長・継続学習させる。

**理由**: 単一デバイス上でゼロから育てたモデルは、情報量の物理的な壁により
長期間まともな言語を出せない。実用に足る AI Reporter に到達するには、言語の
骨格は与える必要がある。独自性は「モデルそのもの」ではなく「育て方（継続学習・
記憶・メタ認知）」で出す。

**却下した代替案**:

- *完全ゼロから自己成長*: 真に新規だが、長期間まともな言語を出せず、AI
  Reporter が実用に届かない。研究純度は最高だが実現可能性で却下。

### 柱2: GPU 依存度 = WASM/CPU フォールバック必須

**決定**: WebGPU に全体を賭けない。Runtime を最初から2実装（WebGPU / WASM）
前提で抽象化する。

**理由**: 最優先環境である iOS Safari の WebGPU は、standalone PWA モードでの
既往挙動差・GPUメモリ上限・compute shader 制約など、このスタックで最も不安定
な部分。ここに単一障害点を作ると、最優先環境で動かないリスクを負う。Runtime
を差し替え可能にしておけば、WebGPU が死んでも全体が動く。

**却下した代替案**:

- *WebGPU 必須*: 速度と単純さは得られるが、iOS で動かない期間はプロジェクト
  全体が停止するリスクを負う。iOS 最優先方針と整合しないため却下。

### 柱3: 最初の検証 = iOS PWA で GPU 学習ループが回ること（Phase 0）

**決定**: 7層アーキテクチャや AI Reporter を作り始める前に、最も細い垂直
スライスで「iPhone 実機の standalone PWA 上で、GPU 学習ループが回り、重みが
永続化・復元される」ことを実証する。詳細は `docs/phase-0-spec.md`。

**理由**: これがプロジェクト成立の最大の未知数。ここが通らなければ設計を根本
から変える必要がある。地盤調査なしに基礎を打たない。

## 2. Substrate（言語器官）の位置づけ ― 「ラッパーではない」ことの担保

柱1で「事前学習モデルを土台にする」と決めたが、これは原則「LLM のラッパーを
作らない / Transformer をコピーしない」と擦れる。この矛盾を次のように解消する。

**決定（推奨デフォルト・改訂可）**: 事前学習部分を **「差し替え可能な凍結
言語器官（frozen language substrate）」** として位置づける。

- substrate は **賢い部分ではなく、トークン ⇄ ベクトルの低レベル変換をする
  だけのダム部品**。原則として重みは凍結する。
- 「思考・推論・記憶・自己評価・概念化・忘却」——本プロジェクトが本当に作りたい
  もの——は、substrate の周囲に重ねる **完全可塑の自己成長層** が担う。
- **制御の主権は Cognitive Core にある**。ラッパーは「LLM に答えさせて整形
  する」構造だが、本設計は逆で、Core が主体、substrate は Core に駆動される
  末端の器官にすぎず、substrate 単体は「答え」を出さない。これによりラッパー
  ではないことを担保する。
- substrate は **差し替え可能な部品** として設計する。当面は既存のオープン
  小型モデルを凍結して使い、将来は自前の小型言語核へ差し替えられる口を残す。

この決定は「実装手段として既存小型モデルを使い(a)、哲学として言語骨格のみを
与え(c)、自作核への差し替え口を残す(b)」という三者の最良点を狙うもの。原則を
厳守して最初から骨格自作(c)に振る選択肢は残すが、Phase 0 が数週間伸びるため、
まずは推奨デフォルトで進める。

## 3. 設計原則: レイヤーは「名前」ではなく「データ契約」で定義する

当初構想の7層（WebGPU Runtime / Language / Representation / Memory Fabric /
Cognitive Core / Reasoning / Meta Cognition）は思想としては良いが、そのままでは
実装の切れ目になっていない。「Cognitive Core」「Meta Cognition」は放置すると
定義の曖昧なバズワードになる。

**決定**: 各層を、その層が「受け取る入力・返す出力・保持する状態」の契約で
定義し直す。層の名前ではなく、層の間を流れるデータ型で設計する。これにより
各層が単体でテスト可能になり、Runtime だけ差し替えれば別環境でも動く。

暫定のデータ契約（Phase 1 以降で確定させる。ここでは方向性のみ記録）:

- **Runtime**: テンソル／カーネル抽象。`tensor`, `matmul`, `backward` 等を
  提供。WebGPU 実装と WASM 実装を差し替え可能にする共通インターフェース。
- **Representation**: 世界を固定次元ベクトルに符号化する層。`encode(x) →
  vector`。全記憶・全推論の共通通貨（common currency）となるベクトル。
- **Memory Fabric**: ベクトル + メタデータのストア。短期／長期／知識／人格を
  「別テーブル」ではなく **同一ベクトル空間内で、可塑性・保持期間・出所という
  属性** で区別する。忘却を「バグ」ではなく「設計された機能」として扱う。
- **Cognitive Core**: 状態遷移エンジン。`state_t + input → state_{t+1} +
  action`。
- **Meta Cognition**: Core の予測誤差を監視し、「学習率を上げる／質問する／
  凍結する」を決めるコントローラ。

## 4. 既知の主要リスク（設計判断に効くもの）

- **iOS Safari / standalone PWA の WebGPU 不安定性** → 柱2・Phase 0 で対処。
- **GitHub Pages が任意 HTTP ヘッダを設定できない** → `SharedArrayBuffer` に
  必要な COOP/COEP を張れない。Service Worker による COEP 注入（coi 方式）を
  検討するが、iOS Safari で効かないケースがあるため Phase 0 で実機確認する。
- **破滅的忘却（catastrophic forgetting）** → 継続学習の本質的難問。Memory
  Fabric の「可塑性属性による区別」と substrate 凍結で緩和する設計とする。
- **iPhone の GPU メモリ上限** → モデルは極小前提。勾配チェックポイント等を
  Phase 2 以降で検討。

---

## 5. ロードマップ（Phase 概要）

```
Phase 0  技術検証: iOS PWA で GPU 学習ループ + 永続化/復元を1本通す
Phase 1  Runtime 抽象 + Representation(encode) + Memory Fabric 最小
Phase 2  Cognitive Core（1ステップ予測 + オンライン更新）
Phase 3  Meta Cognition（予測誤差ベースの制御）
Phase 4  AI Reporter を最初のアプリとして載せる
```

各 Phase は前 Phase の受け入れ条件を満たしてから着手する。
