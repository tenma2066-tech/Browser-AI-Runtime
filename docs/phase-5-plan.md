# Phase 5 計画 ― 生成能力（小型因果 LM を自前実装・クライアント推論）

- 前提: ADR-0003（生成能力の追加・サーバー緩和）
- 目的: 「GPT 的に使える」＝**文章生成（会話）**を、完全クライアント推論・自作
  エンジンで実現する。品質は端末制約内（GPT-3.5 級には届かない）で妥協するが、
  **ユーザーの記憶・概念・人格に接地した生成**という独自価値を出す。

これは複数フェーズにまたがる大工事。Phase 0 と同様、**最も危険な未知数を最初に
実機スパイクで潰す**。

---

## Phase 5a ― iOS WebGPU 生成の実現性スパイク（最優先）

生成は per-token forward が要り、自前 JS では遅すぎる。**WebGPU で回して usable な
速度が出るか、そもそも載るか**を、作り込む前に確かめる。

- ごく小さな因果 Transformer（数層・小 hidden）を WebGPU で forward し、
  自己回帰生成を回す最小実装。
- 計測: iOS Safari standalone PWA で **tokens/sec**、読み込めるモデルサイズの上限、
  メモリ挙動、KV キャッシュの効果。
- **合否**: 実用に足る速度（目安 数 tokens/sec 以上）と、載るサイズが確認できるか。
  ダメなら方針を見直す（さらに小さいモデル / 量子化強化 / 生成をあきらめ会話UI）。

Runtime の WebGPU 経路（テンソル常駐・matmul カーネル）への投資はここで始まる。

---

## Phase 5b ― 小型因果 LM の抽出と自前 forward

5a が通ったら本体を作る。

- **モデル候補**: rinna/japanese-gpt2-small（~110M・hidden768・12層・SentencePiece・
  MeCab 非依存）等。**小型に保つ**（GitHub Pages: 単一ファイル 100MB 制約。必要なら
  チャンク分割・量子化強化・より小さいモデルへ）。サイズが iOS に厳しければ縮小。
- **抽出**（tools/, e5 と同様）: 重みを range/stream 取得 → 量子化（int8）→ compact
  形式で **GitHub Pages に配信**（OPFS キャッシュで再訪はローカル）。トークナイザは
  既存 unigram Viterbi を流用。
- **因果デコーダ forward**（自前）: token+position 埋め込み → N×[**causal** self-
  attention + FFN + LN] → final LN → LM ヘッド（tied 埋め込みで語彙 logits）。
  e5.js の attention/LN/GELU を土台に、**causal マスク**と**生成**を追加。
- **KV キャッシュ**: 既生成トークンの K/V を保持し、1 トークンあたり 1 ステップに。
- **サンプリング**: temperature / top-k / top-p。
- **受け入れ条件**: プロンプトから日本語が生成される（品質は控えめでも可）、
  KV キャッシュで速度が出る、重み bit 一致で保存/復元。

## Phase 5c ― 記憶接地生成（RAG）+ チャット UI

生成を、これまで作った自己成長層に接続する。ここが独自価値。

- **知識は GitHub データ + RAG**: 学習データ/知識を GitHub に置き（バージョン管理・
  更新可能）、埋め込みを用意しておく。生成時に入力へ関連部分を**想起**して
  プロンプトに挿入。**知識はモデルの大きさでなくデータで持ち、増やせば増える**。
  検索基盤は既存の Memory Fabric・埋め込み・想起を流用。
- **記憶接地**: ユーザー入力に関連する記憶・概念・人格（Memory Fabric から想起）を
  文脈としてプロンプトに挿入して生成 → **そのユーザーだけの文脈で答える**。
  （＝ GitHub 知識データ ⊕ ローカル個人記憶 の二源で接地する。）
- **成長ループとの接続**: 会話も経験として記銘（Phase 2a の驚きベース）、概念化
  （Phase 3b）、Meta の質問（Phase 3a）。使うほど各ユーザーで育つ。
- **チャット UI**: 会話形式。ローカル永続化で継続。
- **受け入れ条件**: 記憶に接地した応答が返る、会話が経験として蓄積・概念化される、
  完全ローカル・自作エンジンで動く。

---

## 全体の受け入れ条件（Phase 5 完了）

1. iOS 実機で、自作エンジンによる文章生成が usable な速度で動く。
2. ユーザーの記憶・概念に接地した会話ができる。
3. 会話が経験として蓄積・概念化され、ユーザーごとに育つ。
4. 既存 AI 推論 API を使わない（自作・オリジナル）。完全クライアント推論。

## 正直なリスク

- **モデルサイズ × iOS メモリ**: ~110M int8 ≈ 110MB は iOS で厳しい可能性。5a で確定。
- **WebGPU 生成エンジンの複雑さ**: 自前で causal + KV + サンプリングを WebGPU で
  組むのは本プロジェクト最大級の実装。段階的に。
- **生成品質**: 小型モデルは GPT-3.5 級に届かない。記憶接地で"らしさ"を補う。
- **速度**: WebGPU 前提。CPU では実用速度が出ない見込み。
